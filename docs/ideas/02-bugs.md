# 02｜路線 A 的 bug

以下都可以用 job `16fae7864ca8` 重現（`get_prepared_video` 的 `structuredContent.analysis`）。

## 1. Whisper 在第二段開頭漏轉約 30 秒

- **現象：** `analysis.transcript.segments` 在 `117.9–120.0`「会自动归类到费用这个页面里面去」之後，下一筆直接跳到 `149.6`「就像这个工作台」。120.0–149.6 秒之間沒有任何語音紀錄。
- **證據：** 這段時間畫面上一直有燒進去的字幕，代表講者有在講話。

| 原片時間 | 畫面字幕 |
|---|---|
| 2:00 | 而且还能看到逐年的趋势 |
| 2:04 | 所有上传的资料都能在这里找到 |
| 2:08 | 可以为自己或者家人建立独立的档案 |
| 2:12 | 就能得到一个完全空白的档案 |
| 2:16 | 做这个系统的时候 |
| 2:20 | 当真到陪他们去看病的时候 |
| 2:24 | 我们不一定能说清楚 |
| 2:28 | 最后能变成生活里用得上的东西 |

- **影響：** ChatGPT 摘要把這段誤判成「旁白較少」，還漏掉了「陪爸媽看病說不清病史」這段開發初衷的前半。
- **可能原因：** 切段邊界剛好在 120 秒（`segment_seconds=120`），第二段開頭可能被 VAD 或 `no_speech_prob` 過濾掉了，也可能是 chunk 對齊時的偏移。
- **驗收：** 0–166 秒之間，逐字稿不能有超過 5 秒的空白（片頭片尾除外）。上表的字幕內容要出現在逐字稿裡。

## 2. MiniMax 畫面證據的時間碼壓縮了

- **現象：** 17 筆 `type=visual` 的時間全部落在 0.0–6.9，但影片長 166.6 秒。
- **對照表**（以語音和截圖推算實際時間）：

| 標記的 timestamp | 畫面內容 | 實際約在 |
|---|---|---|
| 0.3 | CareArk 網頁、GitHub 開源 | ~8s |
| 0.9 | 護理師抽血片段 | ~28s |
| 2.4 | 講者：「下面手把手演示」 | ~56s |
| 3.1 | `.env`／DeepSeek 設定 | ~65s |
| 4.9 | AI 辨識檢驗單 | ~104s |
| 6.2 | 原始資料頁、家人檔案 | ~124s |
| 6.9 | 講者結尾 | ~137s |

- **比例：** 大約 20～30 倍，而且不是固定值。看起來是單位或換算錯了，不是單純乘一個係數就能修。
- **影響：** 這次分段主要靠語音時間碼，所以影響不大。但小工具說「時間碼使用原片時間」，畫面證據的時間其實是錯的，沒辦法拿來對時間點。
- **驗收：** 畫面證據的 timestamp 要分布在 0–166 秒，和截圖對照的誤差不超過 5 秒。
